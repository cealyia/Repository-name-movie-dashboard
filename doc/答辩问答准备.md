# 答辩问答准备（一个人版）

> 用法：答辩前一晚把每题读一遍，能用自己的话讲出 70% 即可。
> 括号里是"如果老师追问"的补充，不用背，理解就行。

---

## 一、数据与建模

**Q1：为什么用 5 张表，不用 1 张宽表？**
A：评分数据里片名、类型会重复几百次，全放一张表既浪费空间，改一个片名还要改几百行。
拆成「维度表存描述 + 事实表存行为 + 关联表解多对多」，就是数据仓库的星型模型，
查询时用 JOIN 拼回来。我的 5 张表是 `dim_movie`、`dim_genre`、`rel_movie_genre`、
`fact_rating`、`fact_tag`。

**Q2：10 万行是怎么来的？是不是凑的？**
A：不是。9,742 部影片本身不够 10 万，但「用户 × 影片 × 时间」的评分行为有 100,836 条，
这是 MovieLens 官方数据集的真实记录，不是我造的。事实表才是数据量的来源。
（追问：那你怎么证明是真的？→ 数据集官网写明 100836 ratings，我导入后 `SELECT COUNT(*)` 也是这个数。）

**Q3：数据清洗做了什么？删了多少行？**
A：8 条规则，删了 0 行。主要是格式统一：5 星制 ×2 转 10 分制、时间戳转东八区并派生
`rated_date/rated_month`、类型英文转中文、片名解析年份（13 部解析不出，置 NULL 但不删记录）。
（追问：为什么不删？→ 删影片会连带删掉它的评分，反而让数据量变小、样本有偏。）

**Q4：`rated_date` 和 `rated_at` 不是重复吗？**
A：是冗余，故意的。按月分组如果写 `DATE_FORMAT(rated_at,'%Y-%m')`，10 万行每行算一次函数，
用不上索引。导入时把月份算好存成 `CHAR(7)`，查询就是 `GROUP BY rated_month`，能走索引。

## 二、后端与接口

**Q5：为什么前端没用 Vue？任务书不是推荐 Vue 吗？**
A：两份要求有冲突：选题文件明确写"不引入 Vue/React/axios"，任务书写的是"推荐 Vue 3"。
我选了交集——原生 HTML/CSS/JS + fetch + ECharts，两边都不违反，也少装一套 Node 环境。
（追问：那前后端怎么分离的？→ 后端只提供 `/api/**` 的 JSON，前端是纯静态文件，通过 CORS 允许跨域。）

**Q6：统一返回结构有什么用？**
A：`Result<T>{code, message, data, timestamp}`。前端只判断 `code === 200`，
错误时也能拿到中文提示；如果每个接口返回结构不一样，前端要写一堆 if。
（追问：HTTP 状态码和 code 不是重复吗？→ 不重复，HTTP 状态码给浏览器/网关看，
code 给业务看；我让它们保持一致，400 就返回 400。）

**Q7：接口为什么全是 GET？**
A：这个项目是只读看板，没有增删改，所以按语义全部用 GET。如果有新增，会用 POST 并返回 201。
（自查表第 4 条要求"新增返回 201"，我在文档里注明了本项目无写接口。）

**Q8：排序参数为什么不能直接拼进 ORDER BY？**
A：MyBatis 的 `${}` 是字符串直接替换，前端传 `sortBy=1;drop table` 就能注入。
我做了白名单：只允许 `avgScore / releaseYear / title`，其余回退到 `rating_count`，
并且追加 `movie_id ASC` 保证翻页稳定。

**Q9：分页怎么做的？为什么不用 PageHelper？**
A：自己算 offset，SQL 里 `LIMIT #{size} OFFSET #{offset}`，再单独查一次 `COUNT(*)`。
不用 PageHelper 是因为只有一处分页，多一个依赖要多解释一个东西，而且自己写更能讲清原理。

**Q10：8 个图表怎么保证数字一致？**
A：所有统计接口共用同一个 CTE `movie_agg`：先把"符合条件的影片 + 它们在时间段内的评分数/平均分"
算成一张临时表，KPI、趋势、类型、TOP10 都从它出发。筛选条件只写一次，口径不可能不一致。

**Q11：环比怎么算的？**
A：取与当前区间等长的上一段区间（比如 2015-01-01~2018-09-24 共 1363 天，
上期就是 2011-04-09~2014-12-31），用两期评分数算 `(本期-上期)/上期`。
上期为 0 或超出数据范围时返回 null，页面显示"—"。

## 三、前端与图表

**Q12：图表联动怎么实现的？是前端过滤数据吗？**
A：不是。点击柱子只是把那个维度写回筛选状态，然后重新请求后端，和左侧筛选器走同一条逻辑。
如果前端自己过滤，KPI 和其他图表不会变，用户会看到自相矛盾的页面。

**Q13：一次请求 8 个接口，会不会很慢？**
A：浏览器并发发 8 个请求，每个 50–200 ms，用户感知不到。而且每个接口只返回几十行聚合结果，
不是把 10 万行传到前端。

**Q14：词云那个 bug 说说？**
A：图表一片空白，控制台没有报错。我先对比官方示例，发现唯一的差异是我把 `textStyle.color`
写成了函数。echarts-wordcloud 内部用 `visualStyleMapper` 取颜色，函数取不到值就不画。
改成给每个数据项单独设置 color，并缩短过长标签、调小字号，就出来了。

**Q15：如果现场让你加一个图表，你怎么做？**
A：四步——① 在 `StatsMapper` 加一个查询方法 + XML 写 SQL；② `StatsService` 加一个方法；
③ `StatsController` 加一个 `@GetMapping`；④ `charts.js` 加一个 render 函数，`app.js` 在
`refreshAll` 里调用。最后刷新页面，用 Swagger 单独验证接口。

## 四、工程与个人

**Q16：这个项目你一个人做，三个角色怎么分的？**
A：数据：数据集调研、清洗、建表、导入脚本、数据说明；后端：10 个接口、MyBatis 聚合、统一返回与异常；
前端：布局、8 个图表、筛选联动、表格分页。三块分别有独立的交付物，文档 7.1 里也分开写了。

**Q17：AI 帮你做了什么？哪些是你自己改的？**
A：AI 主要给了骨架和排查思路，比如 CTE 的写法、词云为什么空白。
但具体的表结构、指标口径、配色和布局是我按数据实际情况调的；
词云那个 bug 是我按"对比官方示例"的方法自己定位的，记录表第 17 条写了验证过程。

**Q18：如果数据量再大 10 倍（100 万行）怎么办？**
A：① 索引和分区（按 `rated_date` 按月分区）；② 预聚合物化表，定时跑批；
③ Redis 缓存热点查询；④ 再往上就上 Spark/Hive 做离线计算，看板只查结果表。

**Q19：这个项目有什么不足？**
A：没有缓存、没有单元测试、数据止于 2018 年、没有移动端深度适配。
如果继续做，会先补接口测试，再加 Redis 缓存，最后接 TMDB 补导演和海报。

## 五、演示时的注意事项

1. 提前 10 分钟启动好工程，**不要现场 `mvnw spring-boot:run` 等依赖下载**。
2. 浏览器只留看板和 Swagger 两个标签页，缩放 100%。
3. 数据库窗口提前开好，`SELECT COUNT(*)` 直接回车就能出结果。
4. 代码窗口提前打开 `StatsMapper.xml` 和 `app.js`，定位到要讲的那几行。
5. 讲错不要慌，一句"这块我回去再确认一下"比硬编强。
